## 证据方法与验证边界

使用 Ghidra 11.4.2 和 x86-64 反汇编还原调用、参数、校验及分支；再用 Windows Python `ctypes` 加载原 SDK，将串口交换和 flush 函数在进程内替换为模拟器。SDK 生成真实 TX；模拟器提供 RX，促使 SDK 执行后续流程。**固定文件里的 RX 是合成应答，不能当成实物抓包。**

`Docs/Original/probe-private-sdk.py --dll PATH --output vectors.json` 可以复现。仅允许匹配上述哈希的 DLL，串口名称固定不存在；每个高层 SDK 操作只尝试一次。保存标记固定为 `F9 56 34 12`，Unix 时间固定 `1700000000`。OTA 使用 768 / 777 字节合成文件，覆盖 32 字节包、8 字节尾包及 `FF` 补齐。它们只用于离线测试，绝不可作为设备固件。

SDK 大包读取探针把未初始化栈内容放进 TX 的无效载荷，因此该条读报文的载荷与 CRC 会随运行变化；Swift 将读取载荷清零。其余写操作按固定输入做字节对照。源码不包含解包后的 DLL、反编译 C 或原程序资源。

## 控制帧扩展

沿用 20 字节控制帧，不应用运动参数的输出轴缩放。私有操作时 timeout 位为 0，与 SDK 默认调用一致；普通 FOC 通信固定打开超时保护。

| 功能 | 模式 | raw torque |
|---|---:|---:|
| 清故障 | 6 | -256 |
| 版本 | 6 | -512 |
| 上电标定 | 6 | -1024（出厂）/ -1023（高精度、限位） |
| 序列号 | 6 | -1536 |
| 复位 | 7 | 0 |

版本 RX：26 字节、正常 CRC、字节 3 必须为 `80`，版本 UInt32 位于偏移 10，按高到低解释为 Boot major、Boot minor、App major、App minor，显示十六进制。绝不能从故障寄存器偏移 14 读取。

SN RX：字节 3 为 `82`，偏移 6–17 是 12 字节序列号。旧固件回退 Boot 读取：长度码 7、地址 32 的前 8 字节，加长度码 3、地址 40 的前 4 字节。显示 24 位十六进制。

清故障要求反馈错误寄存器归零，随后停止查询。复位后验证停止反馈；不能只依据写串口成功。

## Boot 报文

TX：`FE EE`, `F0 | id`, `00`, control UInt32, payload, CRC32。

control 的位：0–7=`F0 | id`；8–11=command；12–15=lengthCode；16–29=address；30–31=sector。

lengthCode ≤7 时 payload=8 字节，否则 `1 << (lengthCode - 4)`。TX 长度 payload+12，CRC 覆盖前面的全部字节，使用与公开协议一致的 STM32 word CRC。

RX：`FC EE`、字节 2（低 4 位 ID，bit7=成功）、字节 3（高 4 位长度码，低 4 位 command）、UInt16 地址/分区、payload、8 字节保留尾部、CRC。长度 payload+18，CRC 覆盖偏移 2 至末尾 CRC 前。必须匹配所有响应字段且成功位置位。

| command | 含义 |
|---:|---|
| 0 | 读取 |
| 1 | 写入 |
| 2 | 保存配置 |
| 3 | 擦除分区 |
| 4 | 复位引导 |
| 5 | Swmotor 引导切换 |
| 7 | SN 区间搜索 / 唯一 SN 分配 ID |

分区 0 为配置，分区 1 为 APP。地址为协议地址，不可当作 CPU 物理 Flash 地址。

## 配置流程

- 进入 Boot：广播 Stop，等待 1 ms，向目标 ID 发模式 7，等待 80 ms。
- 普通解锁：长度码 8 读取配置地址 32，取返回的 16 字节；原样写入地址 16。**这是动态挑战回传，不能写死为 AA。**
- 改 ID：先检查目标 ID 是否响应，解锁后写地址 4（8 字节中第 1 字节为新 ID），验证返回新 ID；随后向新 ID 保存并读取地址 4 确认。
- ATB：解锁后写地址 5，首字节 0/1，保存并回读。修改后仍可能处于 Boot，界面提供引导切换。
- 保存：command 2、地址 0，payload=`UInt32 clientTag + UInt32 UnixTime`，最多等待 3 s。SDK 的 tag 为 F9 加 3 字节主机指纹；Swift 使用 F9 加 3 字节随机标记，无鉴权绕过。该标记的设备日志兼容性尚需实物验证。
- 波特率：要求版本分量 Boot≥03.0A、App≥02.15（复制 SDK 的逐分量判定）；读取地址 14，必要时写首字节 `baud/100000` 并保存。Boot command 4 后通过 IOSSIOSPEED 切换主机，再查询停止反馈。支持 4 / 6 Mbps。

## APP 固件升级

1. 文件名 `N1215-288_APP_VVVV_CCCC[_备注].bin`。VVVV 为十六进制 App 版本，CCCC 是字符串 `N1215-288_APP_VVVV` 的 CRC16。CRC16 使用反射多项式 `8408`，初值 0，无末异或。名称 CRC **不校验固件内容**。
2. 文件 8 字节至 128 KiB，尾部补 `FF` 至 8 字节对齐。按整个补齐内容计算独立 CRC16。
3. 进入 Boot，10 次向地址 15 写 1（临时禁止自动引导，间隔 10 ms）。读取地址 32 的挑战，写地址 15：`01 + challenge[0..<12] + 000000`（长度码 8）。
4. 长度码 9 读取 APP 地址 0，以验证长报文通信；失败时尚未擦除。
5. command 3 擦除 APP，payload 同保存格式，超时 3 s。
6. 每包 32 字节（长度码 9），不足时按 8 字节（长度码 7）发送，地址=`byteOffset/8`，超时 1 s。每次比较返回载荷；不一致立即终止。
7. 配置地址 4 写长度码 3：`id, 01, contentCRC16, 00000000`，检查回读再保存。
8. 再次进入 Boot，command 5，要求返回 `OK ATB1`。Swift 额外查询运行版本，与文件名中的 App 版本比较后才报告完成。

升级失败/取消后不自动保存或启动、不自动重刷；界面保留阶段，可重新执行完整更新。若取消恰逢设备已接受保存或启动，软件无法撤销已执行动作，需回读状态。

## 标定

支持出厂、高精度、限位 A + 有符号行程；要求 App major≥2 且 minor≥0A，遵循 SDK 检查。所有输入为输出轴弧度，范围 ±2π；反向坐标同时反转 A 与行程符号。

raw speed=`Int16(Float(travel)*32768*0.5/π)`；raw position 低 16 位为同样缩放的 A，高 16 位为 clientTag 低 16 位；raw kp/kd 拼成 UnixTime。Float 中间计算、向零截断与 SDK 一致。出厂模式 raw torque=-1024；另两种=-1023，高精度使用 A=0、travel=0。

RX 要求 mode6、torque 回显、error=0；speed 低 2 位零行程为 0，否则 2，高精度/限位还要求 bit7；限位模式下位置需在 A 或 A±2π 的 0.02π 容差内。该标定是**上电位置参考**配置，不是自行设计电流/编码器整定动作。

## 重复 ID 修复

原 SDK `Reset_ID` 调用 `231a04030`，递归搜索函数 `231a03420`。Boot command 7、lengthCode 9，载荷 32 字节：下界 SN 12 字节、上界 SN 12 字节、UInt32 操作、UInt32 新 ID。SN 按高/中/低三个 UInt32 小端传输；操作 0 搜索、1 分配。搜索成功回传 32 字节中前 12 字节为 SN、偏移 28 为旧 ID。无字节应答为空区间；收到损坏/冲突应答则二分区间，直至每台设备唯一响应。

Swift 使用广播 ID 15 搜索整条总线，按原 ID / SN 排序；模式 1 保留每个原 ID 的第一台，其余分配未占用 ID，模式 2 分配为 0…N−1。分配回包必须完整回显唯一 SN 和目标 ID；全部分配完成后，执行各设备解锁、同 ID 写入、保存与回读，最后逐台 Stop/reset/80ms/Swmotor。最多 15 台、3000 次查询；单值区间仍冲突则失败，不能把噪声当作新电机。该流程可以中止，已写入的 ID 不会撤销。

`probe-duplicate-sdk.py` 使用同一参数形式。固定文件 `duplicate-vectors.json` 记录 SDK 在两个合成设备（SN=1 和 2^95+3、ID 均为 0）下的 3 次搜索、2 次分配及保存启动报文。两台最终为 ID 0 / 1，SDK 返回成功。合成的冲突应答故意具有无效 CRC。

## 扫描与引导切换顺序补齐

Search_ID_Safe: `FE EE 0F…` 广播停止 → 1 ms → `FE EE 7F…` 广播复位 → 80 ms → `FE EE FF 00 FF 00 04 00 AA…`（command 0，address 4）→ 收集最多 31 个原始 ID 字节，等待 1 秒，不走 FC EE / CRC 解析。空结果再查询一次；串口 I/O 错误采用 500 ms 间隔、重连并重试（最多 3 次）。非法 ID 字节直接失败，不做配置写入。扫描不会自动执行 Swmotor。

Swmotor: 广播 Stop → 1 ms → 目标 ID reset → 80 ms → Boot command 5 → 检查 `OK ATB`。`parity-vectors.json` 来自实际执行原 SDK；Swift 测试严格验证该顺序及等待参数。

全总线模式 1 / 2 的完整发送顺序见 `bus-vectors.json` / `reorder-vectors.json`，均由对应探针生成；RX 为合成数据。
