## 本次差异与边界

- 原 GUI 自动检测入口 `0x14000e6c0`，worker `0x140004bd0`（Qt 元调用 `0x1400309d0` case 14），完成处理 `0x1400188a0`。它不是周期后台扫描，也不是 SDK 引导 `Search_ID_Safe`。worker 的SDK函数表位于对象+0x10：依次Set_Id、Set_Mode(Stop)、Set_OTP(0)、各控制值归零、Com_Motor_Once；0表示在线，-4表示无应答，其余异常。原生刻意保持保护开启，使用 0–14 的 protected Stop 应用探测，10ms 每 ID；不会清锁存或自动进入 FOC。探测到故障/锁存仍展示反馈，由后续启动流程检查。
- 限幅来自 DLL `Set_Control_Data_Out` / `Set_Control_Data_Rotor`，即四个 Int16 和一个 Int32 的完整有符号范围；这是表示范围，不是电机额定负载范围。Stop 仍要求五参数全零。
- 广播无 ACK，接收计数和曲线只来自逐台真实模拟反馈。每台约 10Hz 的监测额外发送当前统一参数；发送统计包括这些帧。发现列表无法证明物理总线上没有无响应、重复 ID 或后接入设备。
- 异步使用独立发送截止时间、非阻塞接收与有界在途队列；不在每次发送前清接收缓存。按 ID/FIFO 匹配，超时请求先剔除。协议无事务编号，同 ID 的延迟旧回包仍有不可完全消除的歧义。
- 所有运动仍保持超时保护；正常反馈新鲜度 500ms；普通逐台轮询要求 ID 数/总线频率 <0.5s。广播有单独约100ms/ID监测。0Hz 完全暂停控制发送，取消时发送保护开启的 Stop。
- UI 刷新仍为20Hz，与控制频率和启动锁存清除无关。
