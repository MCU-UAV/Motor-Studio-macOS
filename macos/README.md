# Motor Studio for macOS

为 **J288 / S288** 编写的原生 Mac 调试客户端。使用 **SwiftUI、AppKit 原生曲线绘制、Darwin / IOKit 串口**，无需 Qt、Python、Wine 或 Windows DLL。

**已在 macOS 26.5.1 / Apple Silicon 本机完成 Release 编译和演示验证。** 本机使用 Swift 6.3.3 / SDK 26.5，原生运行测试通过；没有连接真实电机。完整原版功能差异见 [安装包实现分析](Docs/Original/INSPECTION.md)。

## 在 Mac 上运行

需要 Xcode 26 或对应 Command Line Tools（包含 macOS 26 SDK）。运行最低系统为 macOS 14：macOS 26 使用系统 Liquid Glass；macOS 14–15 使用原生磨砂材质。支持 Apple Silicon 与 Intel，分别编译或生成通用包。

```bash
cd Unitree-Motor-Assistant/macos
open Package.swift
```

在 Xcode 选择 `MotorStudio` scheme、`My Mac`，点击运行。也可以：

```bash
swift run MotorStudio
```

首次预览无需电机：打开界面顶部的「演示」，点击「连接」，再点「开始通信」。多电机页可扫描三个演示 ID。演示曲线明确标注为模拟数据，CSV 包含 `demo` 列。

## 生成可双击的应用

```bash
bash scripts/build-app.sh
# 同时支持 Apple Silicon / Intel：
bash scripts/build-app.sh --universal
```

生成 `dist/Motor Studio.app` 和 `dist/Motor-Studio-macOS.zip`。完整 Xcode 下构建脚本执行协议测试；仅 Command Line Tools 时明确跳过 XCTest。两者均执行原生模型/采样测试、编译、生成原生图标并做 ad-hoc 签名。公开分发仍需要开发者自己的 Developer ID 签名及 Apple 公证；本工程未配置证书。

仓库包含 `.github/workflows/macos.yml`，可在自己的 GitHub 仓库触发，下载构建产物。本次未推送仓库或运行远端 CI。

## 已实现

- 单电机工作台：输出位置、速度、扭矩、两路温度、电压、错误与警告。
- 目标位置、速度、扭矩、Kp、Kd（按原 SDK 整数范围限幅并回填，非有限数拒绝）；停止 / FOC 模式；回车 / 应用或逐字实时输入，控制期间固定开启超时保护。
- `/dev/cu.*` 串口枚举，4 / 6 Mbps 主机速率，8N1。macOS 非标准波特率使用 `IOSSIOSPEED`。
- 多电机 ID 0–14 选择、应用自动检测、原 SDK 引导扫描、独立/统一参数；20 行完整反馈表按电机并列。ID15 广播控制在检测和逐台保护确认后启动，另以约10Hz/台监测实际反馈；检测本身保持停止。
- AppKit 多曲线、目标/反馈、刷新暂停、横纵缩放、历史浏览和游标；30 秒至 1 小时按时间保留完整记录、CSV 导出。
- 输出端 / 转子端控制、反馈和曲线切换；位置、速度、扭矩与增益均换算。同步请求应答与异步流水发送/接收可选；总线目标0–10000Hz，0暂停，分别显示实际发送/接收率。
- 默认断开、零控制参数、每次启动先 Stop/零参数清锁存，再 Stop/零参数重新开启保护并确认；连续三次单个 ID 无响应、故障或超时状态时请求停止。
- 停止、断开与退出时广播停止整条总线，再逐个验证已知 ID；广播自身没有应答，不据此报告确认成功。
- macOS 26 Liquid Glass、原生图标、减弱透明度辅助功能适配。
- APP 固件升级：原厂名称/型号/版本检查、分包写入、逐包回读、CRC、保存、启动版本验证与阶段进度。
- 私有配置：改 ID、设备 4 / 6 Mbps 切换、清故障、复位、版本 / SN 查询、ATB 开关、Bootloader 与引导切换。
- 出厂 / 高精度 / 限位 A 与行程三种上电位置标定，检查设备模式与位置回读。
- 维护独占串口，阻止控制循环、断开及退出干扰；失败或取消保留阶段，不显示完成。

## 启动前保护确认

连接只打开串口。点击开始后，后台对每台电机先发送 Stop/零参数/timeout=0 清除锁存，紧接着发送 Stop/零参数/timeout=1；两次反馈均需正常，全部通过才发送控制参数。失败或取消会保持停止并尝试恢复保护；运行中再触发超时仍立即停止，不自动清除后继续运动。界面 20 Hz 刷新率与该流程无关。单台轮询周期需小于 0.5 秒；超过 500 ms 没有正常保护反馈时，禁止沿用旧启动确认继续发运动帧。

硬件无关回归：先 `swift test`，再 `python3 scripts/test-startup-runtime.py`。后者编译真实采集引擎并连接有锁存状态的模拟串口，不连接电机。

## 连接实物

1. 使用适合 J288/S288 **半双工 TTL** 总线的 USB 适配器，安装其 macOS 驱动；确认实际支持电机配置的 4 或 6 Mbps。原版默认 6 Mbps。
2. 选择设备、当前波特率和正确 ID，点击连接。**连接只打开串口，不自动发送电机命令。**
3. 首次使用先选「停止」模式并开始通信，确认反馈字段正确；固定电机和负载后，再以小幅目标验证 FOC。
4. 选择输出端或转子端输入；切换时自动换算已有参数。CSV 始终使用列名标注的输出端单位。协议表示范围不等于连续工作额定值。
5. 「扫描在线 ID」按原 SDK 广播停止、复位并读取原始 ID；扫描不改写 ID，可能留下 Boot 状态，可在设备工具执行引导切换。总线应仅由本应用控制。

软件停止依赖通信，不能代替硬件急停。设备超时保护约 1 秒，应用可检测异常并尽力发送 Stop；断电、拔线或异常退出时无法保证收到停止确认。已配置的总线频率是目标值，桌面系统不提供硬实时保证，多电机共享总线频率。

## 设备工具

连接实际设备并进入待机后，打开「设备工具」。查询版本可直接使用；写配置前确认总线只连接当前电机并固定负载。每次写入前显示目标与参数供核对，演示模式不会模拟维护成功。

固件必须使用原厂 J288 / S288 APP `.bin` 文件，保持原始文件名。原生版还原了安装包 SDK 的解锁、擦除、分包、回读、保存及启动流程；名称 CRC 与内容 CRC 分开处理。中断后保留电源与串口，重新执行完整更新。修改 ID / 波特率中断时可能已经写入新值，会话会关闭；界面保留实际主机速率，请确认新旧值后重新连接。

详细字节布局、SDK 地址、离线探针、验证边界见 [私有协议移植记录](PRIVATE-PROTOCOL.md)。**本次没有真实电机，也没有实际刷写或标定。**

## 总线修复与剩余差异

整条总线重复 ID 修复按 96 位 SN 搜索，保留已有唯一 ID，重复项分配空闲 ID；另提供全部设备按原 ID / SN 排序后重排为 0…N−1。全部分配与保存完成后才逐台引导切换。

原版持续临时关闭引导的后台循环、语言切换和 Bootloader 自身刷写仍未实现；IM6014 按用户范围排除。原生异步使用独立发送 / 非阻塞接收、单个在途请求，不复用 Windows SDK 的线程 API。本机性能实测与限制见 [本地构建记录](LOCAL-BUILD.md)。

## 性能结构

后台 `AcquisitionEngine` 独立调度采样与故障停止；`RecordingStore` 保留原始记录并在后台生成峰值包络、CSV。界面采用 Observation 属性级观察，数值快照目标 20 Hz，曲线拉取目标 20 Hz，始终只处理最新显示请求。曲线以 AppKit 直接绘制，避免逐点 SwiftUI 图表更新。

```bash
bash scripts/test-native-runtime.sh
```

此测试不依赖 XCTest，实际编译并执行本机 Observation 模型、后台采集、取消、记录与 CSV 路径。

## 2026-11-14 性能版

按电机增量维护 32 点块与分层 min/max 摘要；短窗口直接处理，长窗口查询索引。记录原始值不降采样，CSV 仍导出保留期内的全部记录。绘图区缓存路径、网格、图例和文本，游标用二分查找；无新数据不重建路径。图表不可见、窗口隐藏或最小化时跳过绘图查询，数值面板暂停更新，后台采集继续。

数值面板目标 20 Hz，曲线目标最多 20 Hz。性能版包标识为 `io.motorstudio.desktop.performance`，可与此前本地版并存。没有修改远端项目或主会话本地目录。详细实测见 `PERFORMANCE.md`。

实时位置、速度、扭矩、编码器和通信计数使用 `LiveReadout`：在原生文字视图内观察数据，更新时仅重绘文字，避免数值变化进入 SwiftUI 外层布局。
